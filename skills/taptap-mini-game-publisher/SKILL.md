# TapTap Mini Game Publisher（官方文档研读版）

> 基于 2026-11-03 可访问的 TapTap 官方开发者资料，属**二次整理与执行工作流**，并非 TapTap 官方发布的 Skill。此 Skill 不包含任何平台凭据、不自动提交审核、不假定账号已经取得资格。官方文档可能更新，发布前须实时校核。

## 目标与使用边界

为用户的现有游戏提供**可验证、分平台、最小权限**的 TapTap 上架实施方案。以中国大陆区为默认，但必须先核实实际目标市场。可用于文档核对、代码扫描、构建建议、素材检查、CI 预检、广告逻辑测试、工单准备、正式上架前准备。

**不可宣称**已获得软著豁免、备案通过、广告开通、真实收入、平台审核通过，除非有对应实时证据。不得把 APK SDK、Tap 小游戏 WebGL 接口、H5 MCP API、TapTap 制造插件混用。若没有访问平台/浏览器/CLI 的能力，只能提供操作指导，不能假称已操作。

## 强制工作流

### 0. 先检查，再改动

分析项目目录、`package.json`、`project.json`、`assets/`、`dist/`、引擎文件、已有上架资料与游戏包。优先使用已知上下文，避免要求用户重复说明。对以下字段创建**项目档案**：

| 字段 | 示例 | 是否确认 |
| --- | --- | --- |
| 游戏名、开发者主体、目标地区 | 我是CEO / 个人 / 中国大陆 | 核对 |
| 游戏形态 | H5 / Tap 小游戏(WebGL) / TapTap 制造 / APK / 未知 | 必须确认 |
| 引擎与构建脚本 | HTML+JS / Cocos / Unity / 其他 | 必须确认 |
| 可游玩/可付费 | 免费、IAA、IAP、付费下载 | 必须确认 |
| 联网与身份系统 | 离线 / 平台 API / 自建后端 | 必须确认 |
| 当前后台资质状态 | 已通过/审核中/待补/被驳回 | 基于截图或实时后台 |
| 软件著作权/版号/备案 | 有/无/审核中/未知 | 不得猜测 |
| 商店素材/隐私政策/广告平台 | 已完成/待补 | 证据化 |

若形态不确定，**禁止直接给出发布专用命令或 API 代码**。查阅 `references/02-platform-routing.md`，先完成定位。

### 1. 路由官方文档，不跨形态使用

- **H5**：平台托管 H5；核对 H5 MCP 安装与广告接入指南。当前 MCP 官方明确仅支持 H5。SDK 方法必须以 H5 对应文档/本地实际工具为准。见 `references/04-build-packages.md`、`references/07-ai-cli-mcp.md`。
- **Tap 小游戏（WebGL）**：Unity/Cocos 等转换并用 TapTap 指定工具产生 ZIP；登录/云存档/排行榜/广告参阅小游戏 API；包体上传目前以**开发者控制台**为准。见 `references/04-build-packages.md`。
- **TapTap 制造**：使用其作品及本地插件途径；广告按制造对应路径，不能照搬小游戏 ZIP/CLI 命令。
- **APK/PC**：使用相应 TapSDK 与发布规则；不要套用小游戏包体限制。发现涉及 IAP/付费时执行资质升级复核。

### 2. 逐项做资质判定，不做一刀切结论

阅读 `references/03-compliance-filing.md` 和 `references/09-conflicts-and-rechecks.md`。

1. 核实主体实名认证、资质页面当前判定依据与游戏形态。
2. 无内购不等于备案豁免：普通小游戏正式发布前核对小游戏前置备案。
3. **没有软著**：不能直接判定“必定无需软著”，因为官方不同页面对证书/权属的要求存在差异；以当前游戏后台和工单书面答复确定。
4. **没有自有域名/服务器**：检查 H5/平台托管 vs 自建服务，且不能将“无自有域名”推导为“免 ICP/免备案”。
5. 仅小游戏形态的防沉迷平台能力与同时发行 APK 的责任分开核查。
6. 隐私政策和隐私检测必须与实际行为、SDK、广告数据用途匹配。**禁止使用 TapTap 论坛帖承载隐私政策**。

若资质“审核中”，标记 `BLOCKED_PENDING_PLATFORM`，继续完成可并行的包体和隐私工作，但**不宣称可正式上线**。

### 3. 生成或检查包体

根据形态运行对应构建与自测，参阅 `references/04-build-packages.md`。可执行本地**静态**预检：

```bash
python scripts/preflight.py --project . --target tap-mini --package ./build/game.zip --version V1.0.0
python scripts/preflight.py --project . --target h5 --asset-manifest ./asset-manifest.json
```

结果只表示**本地静态检查**：不能替代 TapTap 上传解析、真机自测、备案、隐私合规审核。包体限制官方存在冲突，不把本地阈值当成审核结论。

### 4. 接广告及必要能力

阅读 `references/05-ads.md`，按实际形态选择：H5/制造广告入口与 Tap 小游戏 Dirichlet。首选激励视频；需要真实回调后才发奖，发奖要幂等、防止重复发放、支持广告失败兜底和用户自愿退出。接入前审查第三方隐私披露。禁止虚构 SDK 方法、凭据、广告位 ID。

如需登录、排行榜、云存档，先读官方实际 API 文档，并判断其前置条件：服务端换票/令牌、平台身份、周期结算、存档冲突与恢复策略等。参考 `references/08-iam-ceo.md`。

### 5. 整理商店材料与合规验收

阅读 `references/06-store-review.md`。逐张核对：图标、横图、方图、真实实机截图、实机录屏、版本说明、适龄分类、隐私政策、版权证明。对缺失项目输出文件名、尺寸、类型、内容标准与责任人。宣传设计图不代替真实游戏截图。

### 6. 上线前建立证据清单并预检

执行以下门槛（任一阻塞项未通过，不给 `READY_TO_PUBLISH`）：

- 形态明确，测试包与最终提审包一致；平台解析/运行通过。
- 包体大小和格式以该类型**当前后台/工单**规则为准。
- 实机游戏核心循环完成、功能按钮可用、重启/断网/存档测试通过。
- 当前必须的资质全部通过（或有官方批准的替代路径）。
- 隐私链接可访问，文本与实际收集/SDK一致，隐私检测通过。
- 素材与实际画面一致，广告回调/频控/奖励测试通过。
- 商店信息和发布地区/时间核对无误。

报告状态仅允许：`READY_TO_REVIEW`（可提交人工审核）、`BLOCKED`（有明确阻塞）、`NEEDS_VERIFICATION`（平台条件不清楚）；平台审核通过也不等于已上线。

### 7. 平台操作必须获得明确授权

建立游戏、更新素材等写操作执行前提供变更预览；**提交审核/撤销、上线/下线、删除、权限变更、广告结算和涉及用户数据的操作**，逐项取得明确授权。CLI 可用时优先 `--dry-run` 与官方 `schema` 核对；切勿暴露 `client_secret`、登录凭据或用户个人资料。参阅 `references/07-ai-cli-mcp.md`。

## 回答与交付格式

默认产出以下 6 部分，按用户实际任务缩减：

1. **当前项目事实**（已证实 / 需确认）；
2. **选择的发布路线**（说明为什么是这个类型）；
3. **资质矩阵**（必须 / 按条件 / 不确定，列官方链接）；
4. **实施变更清单**（文件、函数、依赖、风险；未经批准不执行危险动作）；
5. **验收结果**（静态检查、真机测试、后台审核分开）；
6. **阻塞项与下一步**（最短完成路径，避免重复工作）。
