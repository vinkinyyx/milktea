# 资质、备案、隐私与防沉迷

> 适用：中国大陆 TapTap 游戏发布辅助检查。此处是官方文档整理，不替代主管部门认定、平台审核结论或法律意见。每次正式上架前重新确认后台具体“判断依据”。

## 普通小游戏前置备案实际步骤

后台入口：`商店 → 小游戏管理 → 小游戏资质 → 小游戏前置备案 → 提交核准信息`。

**阶段 A：填写核准资料**

- 检查开发者认证有效且姓名一致。
- 选择用于备案的实际小游戏包体；包体内容与最终提审版本一致。
- 填写软件著作权人名称，与有效权属材料对应；没有软著证书不能编造登记号。
- 上传游戏内容介绍说明，写明分类、核心玩法、功能、是否联网/内购/广告。已持有版号时按后台引导处理不同资料项。
- 个人主体的小游戏负责人**必须为认证主体本人**；按要求填写证件、手机号、邮箱、应急联系方式。
- 上传清晰、真实、有效的身份文件；授权书/承诺书按页面判断是否需要。

**阶段 B：电子化核验**

- 生成核验码；由负责人微信/支付宝扫码完成核验，确认核验结果；不得代替本人核验。

**阶段 C：正式提交、短信、结果**

- 提交后预计无材料问题约 20 个工作日；文档称初审约 12–16 个工作日；收到工信部核验短信后通常需在 24 小时内完成，否则可能退回。
- 审核通过后查看服务核准号、主办单位、服务名称。
- 截图或状态为“审核中”时不得标注“备案完成”。

## 隐私合规技术审计

1. 查找首次弹窗：玩家是否可以看到用途和选择同意/拒绝？不能在未同意前启动非必要采集的第三方 SDK。
2. 清点数据流：SDK、用户 ID、设备信息、联网地址、广告请求、统计事件、客服邮件；做**实际收集表**。
3. 政策文本包含：个人/工作室真实运营主体及联系方式、信息类别、用途、共享方/SDK、存储方式和期限、用户权利、注销/删除渠道、未成年人处理与更新机制。
4. 链接必须公开可读、与游戏内版本一致，文本清晰、排版规范；**不要使用 TapTap 论坛帖**。
5. 接入广告后更新 SDK 清单，再运行平台隐私检测；不要用简单模板假装已经合规。
6. 不要在报告或工单中泄露身份证号、真实手机号、银行账号、登录口令；只报告状态。

## 发布判断

只有“平台审核已通过”的资质才能标注 `PASS_PLATFORM_VERIFIED`；其他是 `PENDING`/`NEEDS_CLARIFICATION`/`REJECTED`。一张历史截图不能代表当前状态。若出现资质缺项，优先补政策/内容/包体等可并行事项，不为了“先上架”绕过审核。
