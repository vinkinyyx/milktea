# P3-C · 首发、运行观测与回退

## 进入条件
P3-B全部硬规则通过，真实平台账号/资质/素材音乐字体授权齐备。未定主体发行问题必须按实际平台解决；本文不替代审批或保证过审。

## 实现文件与配置
server/ops/FeatureFlags.ts管理recordingReward、publicRank、daily、ads，默认新增功能关闭；客户端只读公开开关，关停不依赖重新发包。server/ops/Health.ts区分进程存活和数据库/验分可用。
server/ops/Metrics.ts记录启动失败、崩溃、保存冲突、核验积压、发券拒绝/成功/重复、事务失败。日志以runId/requestId关联，不记录登录code、token或原始视频内容。故障告警发往开发者配置的渠道，不能替用户擅自对外发消息。

## 发布执行顺序
1. 在测试环境从空库和上一版本库各部署一次；备份→迁移→新旧客户端读写兼容→回退演练。
2. 固定构建版本、rulesVersion、资源摘要、服务器版本、迁移号。确认调试调分入口不存在于公开包。
3. 检查隐私、反馈入口、系统必要能力、宣传素材与真实玩法一致；提交审核并记录真实返回。
4. 小范围灰度，观察真实设备错误/验分队列/券账本；有B0/B1关闭相关入口并修复。没有流量就写“样本不足”，不宣称留存稳定。
5. 审核通过并实际发布后回读平台状态，记录链接和时间；不以“上传成功”当已上线。

## 回退设计
App版本可回退，数据迁移优先可兼容的增加字段；删除字段、改币值/券规则不能依赖一键回滚。上线前备份有实际恢复证据。规则版本永远写入run，活动局按启动时规则结算。
奖励紧急关闭时拒绝新prepare，已有已核验证据按记录的兼容政策处理；不得关入口同时丢掉已扣券账本。验分故障将成绩PENDING，不把全部改VERIFIED或清空玩家数据。
客户端无法连接显示离线练习入口和云档状态，不显示已入榜。旧客户端不兼容返回UPGRADE_REQUIRED并保留进度。

## 验收交付
交付release-checklist、构建与配置摘要、审核/发布实际结果、回退演练、匿名观测报表、未解决项和反馈处理办法。资质/审核没完成则明确“待外部完成”，不把文档编写当公众首发。
