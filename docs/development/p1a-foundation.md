# P1-A · 工程、坐标与物理基础

## 进入条件和本阶段边界
已读P0、物理分册和公共契约。只实现工程骨架、杯和 PhysicsLab，不提前接联网奖励。开发者安装 Cocos Creator 3.8 LTS 的具体补丁后，在 evidence/P1-A/版本/environment.json 记录编辑器、构建目标、集成物理后端及配置摘要；提交工程设置和依赖锁文件。

## 场景与坐标
设计面750×1334DU，世界原点左下；UI局部原点可不同，转换集中在 CoordinateMapper。杯底(195,260)到(555,260)，上口(115,1060)到(635,1060)，危险线1000，出生中心1130。CupGeometry接收中心、底/顶宽、底/顶高和宽度倍率，输出左/右/底静态边。边的厚度和端点连接必须经穿透试验确定，画面内缘与碰撞内缘一致。
动态小料使用圆形刚体、中心锚点；美术高光/表情子节点无碰撞。spec中100DU=1物理单位只是本项目物理坐标约定，不等于Cocos内部PTM默认值。适配器负责转换，业务代码只存DU。

## 单位与时间验证
1. 空场景放无阻尼圆，从已知高度静止释放，关闭接触；0.5秒理论位移122.5DU，1秒490DU。离散积分允许约一个固定步位移的误差，记录实际后判断转换是否正确。
2. 比较30fps与60fps渲染下120个物理tick的位置和速度；业务时钟应都恰好120步。不要以渲染帧数作为物理步数。
3. 先确认所选Cocos版本的自动步进与物理后回调。默认优先使用引擎固定步进；若必须手动步进，先禁用自动步进并记录理由。一个项目只选一种拥有者，禁止自动与手动同时驱动。
4. 页面落后台停止推进；回来不得补算后台几十秒，也不能用无限追帧卡死主线程。后台时间不计危险倒计时。
5. 旋转屏幕/安全区变化只变显示缩放，世界坐标和杯体不重建，不改变比分。

## 物理参数与接触边界
从配置读取重力、密度1、摩擦0.25、恢复0.12、阻尼0.05/0.25、线速上限12单位/秒及角速12rad/秒。求解迭代8/8是试验初值，不保证集成后端暴露同名设置。缺失API应记录映射或限制，不能编造调用。
接触回调只登记规范化父ID对，不销毁或创建刚体。物理步后才允许修改世界。begin/end维护持续接触集合；销毁对象时清理所有相关对。Adapter只返回实体ID与几何，不导入UI和排行榜。

## 执行清单
先创建版本化空工程并确认实际启动/构建方法，记录真实命令，不能凭空假设 npm run dev。然后接配置、坐标映射、杯、一个圆、三圆、九种圆、固定步计数，最后加压力和重开工具。
开发依赖不得执行未经检查的上游脚本；本项目技能快照只提供方法参考。

## 失败与验收
- 加载失败展示“配置读取失败，重试”，禁止用空数组假装游戏启动。
- 三圆静置60秒不穿杯；同级不同级都可碰撞；最高级圆能放入最窄杯底。
- 连续20次重建PhysicsLab，实体数/监听数回到初值，没有旧碰撞回调。
- 固定种子、固定120tick在同一环境可复现；若跨环境偏差，记录，禁止先承诺跨端逐帧一致。
