# 小料直柱堆积：物理根因与自然落料设计

## 1. 现象与证据

用户截图小料在中线如串珠叠高。正常颗粒堆积本身合理，本轮要解决的是**长期精确沿同一竖线、没有自然侧向散开**。不能承诺圆形颗粒永远无法短时平衡，也不能把所有堆叠都消除。

代码确认：`RunEngine.tryAutomaticDrop`所有投放x固定cup.center_x_du，初速`{x:0,y:0}`、角速度0；`CocosPhysicsAdapter.createBody`使用CircleCollider2D，合成仍按对称父状态生成子体。对理想完全对称初态，离散刚体解算没有真实世界的小偏差，纯竖向受力可长期保持对称；摩擦/休眠可能维持或放大可见效果。

已运行当前Debug真实Box2D：seed1、静止杯、1800步、30投放、14体，全部x375、vx0；每60步记录的横向跨度最大仍0。多个体当时未休眠，所以“直接关休眠就好了”不成立。无lastTickFault，说明它不是被已有异常保护捕获的坏状态。

贴图有透明边，当前显示边长为2r/0.9，不据截图直接认定碰撞体尺寸错误。需叠加半径/圆轮廓验证，排除可见间隙、深穿透、悬空和接触解算问题；合成新体半径变大还需检查相邻重叠，不能只加随机量后忽略真实几何错误。

## 2. 第一阶段：落料处确定性微偏移

保留杯子可移动、出料口在世界中固定，不跟着杯中心移动。每颗料在固定出料口附近有很小且可预览的偏移/横向初速，用来破坏完美对称；不是全杯抖动，也不是落在空中后随意改位置。

建议待测初值：

```text
spawn_x_offsets_du = [-16,-12,-8,-4,4,8,12,16]
spawn_vx_du_per_second = [-12,-8,0,8,12]
spawn_angular_speed = 0（第一版不靠转动制造效果）
spawn_center_world_x = 375
```

16du在390宽约8.3屏幕像素，不变成满屏随机投放，也不显著破坏接料判断。起始x/vx两次独立均匀选择，长期左右无偏。具体幅度需20种子静止杯和移杯压力比较后定，不以文档数字即宣称自然。

预览与下一实际出料位置必须一致：新增`SpawnDescriptor{level,xDu,vxDuPerSecond,angularVelocity}`，在下一颗准备好时生成并缓存，渲染落点标记/预览使用同一描述符。下一颗的等级仍来自原等级权重流，不受特效随机数影响。

`canSpawn`改检查实际planned x/radius，不再只检查375。杯口被挡、晃杯中、后台或自动重试时保持同一descriptor和随机状态，不反复抽签找可落点；合法成功创建才消费descriptor并准备下一颗。创建失败/物理事务失败必须回滚descriptor、两个RNG状态、nextDueTick、实体ID和等级序列，不能消耗随机数后悄悄换料。

手动DROP若仍留在Debug/兼容路径，其用户指定x保留，不偷偷叠加自动微偏移；新的自然性参数仅用于自动模式。

## 3. 随机流与存档

禁止使用Math.random、当前时间或渲染帧数产生物理扰动，禁止每帧持续给小料加噪声。新增独立spawnRng流，不消耗现有`rng.nextLevel`，确保同seed的等级序列和原权重独立。

建议新RunSnapshot schema4：新增`spawnRng:RngState`及`autoDrop.pendingSpawn:SpawnDescriptor`（名称按契约统一），初始spawnRng由初始seed和固定非零salt通过明确uint32混合算法初始化；算法版本固定、零值修正为固定非零种子。存档含state/drawCount/pending descriptor，校验有限值、范围、等级一致、算法版本，checksum覆盖它们。仅种子相同不足以证明不同设备Box2D逐位确定，跨宿主只要求生成序列一致及各自物理合法。

快照事务必须保存/回滚该流；恢复后用pending descriptor，不能重新生成造成下一料跳位。表现用独立effect seed（可由eventId哈希），不反向消耗物理流。暂停/换表现档/开关减少动态/截图均不改变落点。

初始流算法建议固定为`spawn-xorshift32-v1`，混合规则如下（设计初值，不是当前运行已存在的代码）：

```typescript
function spawnSeed(seed: number): number {
  let x = (seed ^ 0x9e3779b9) >>> 0;
  x = (x ^ (x >>> 16)) >>> 0;
  x = Math.imul(x, 0x7feb352d) >>> 0;
  x = (x ^ (x >>> 15)) >>> 0;
  x = Math.imul(x, 0x846ca68b) >>> 0;
  x = (x ^ (x >>> 16)) >>> 0;
  return x || 0x6d2b79f5;
}
```

之后使用现有xorshift32转换核心、独立state/drawCount，每个descriptor恰好取两次：`floor(nextU32()/2^32 * offsets.length)`选择x偏移，下一次同样选择vx。seed1的spawnSeed应为2767685996，前五个拟定`(xDu,vx)`为`(391,8),(363,8),(367,0),(387,-8),(383,8)`；仅用作生成器金样，不代表已通过物理自然性验收。预生成pending后流已消费这两次，后续阻塞重试不得再消费。

本轮升rulesVersion并保留历史成绩分桶。现有旧schema3局若直接迁移为新落料会改变旧规则：优先保留旧规则继续，若实现不支持双规则，则保留旧原始槽、明示确认重开，不能静默改旧局或清空最好成绩。V1/V2/V3历史读兼容、未知未来版本写保护继续测试。

## 4. 第二阶段排查（仅第一阶段不足时）

从真Box2D测：接触法向、penetration、半径/贴图对齐、合成子体与邻居重叠、速度钳制、sleep状态及合成替换时序。若微偏移仍长期形成柱或严重重叠，先修确定的几何/解算缺陷，再考虑摩擦/阻尼微调。

暂不改圆碰撞为随机多边形，不全局关闭休眠，不把迭代次数无限提高；这些会改变成本与平衡。若确需形状改动需独立对照、重新校准九级半径/合成空间/杯宽，不能当小补丁混入。

不加“检测柱子后瞬移散开”或“无条件给所有物体横向踢一脚”的隐藏规则。老对称局进入新版本也不凭空自动散开；允许用户显式晃杯，或明确重开新规则局。

## 5. 量化与验收场景

1. seed1旧基线30秒复现保存；新规则相同等级序列、20种子各至少30秒（若正常结算提前终止，记录原因，不强行续命）。
2. 记录每颗spawn x/vx、dropIndex、rng与pending descriptor，以及每体position/velocity/radius/sleep。检查左右分布、真实滚动、接触/合成、危险与溢出。
3. 定义诊断柱：≥5个已落入/受支持颗粒，中心x跨度<4du、高跨度>180du，持续>180tick。该指标只用于验收/诊断，不在正式玩法触发自动作弊力。新20种子不应持续出现该长柱；正常短暂3颗叠放不视为bug。
4. 自然散开不是只看x!=375：检查底部有侧向滚动/空间占用，不能产生浮空、明显穿透/爆炸。真实碰撞容差按当前集成后端和已有几何压力标准，不任意放宽断言制造通过。
5. 静止杯、快速左右移杯、杯口被挡重试、晃杯、合成连锁、最高九级、200体、保存恢复、后台/广告、30/60/120Hz表现均测。正常不可避免的杯满/洒出仍按规则结算，不能靠扰动保证玩家永不输。

参考[Cocos3.8物理系统](https://docs.cocos.com/creator/3.8/manual/zh/physics-2d/physics-2d-system.html)及安装Box2D后端，具体API以Creator3.8.8为准。最终应展示接入前/后同seed对照录像和数值轨迹，不能以一个随机碰巧散开的截图关闭PHY-01。
