# 洒出后看广告复活：产品和状态详细设计

## 1. 规则

只在现有正式判定`SPILLED`且本局尚未成功复活时提供。`CUP_FULL`、主动放弃、技术异常不触发此广告点。每局最多一次**成功复活**；取消/未看完/失败不计次数，仍可在当前待处理失败中手动重试，始终一次展示在途。第二次洒出直接正常结算。

保留同runId、失败时已经提交的score/maxLevel/dropIndex、等级与spawnRNG、下一颗描述符、已消耗晃杯及额外库存，后续合成继续正常加分。不是新局，不清分，不重复结算，不回滚到几秒前刷同一份得分。成功复活标记assisted；未看或未成功不改变成绩桶。

## 2. 判定与时序

当前`RunEngine.advanceOneTick`为物理->合成->danger/spill->end，`GameRoot`在SETTLING自动commitResult。新功能必须在end之前引入“洒出待决定”，不能先清run写lastResult再尝试复活。

建议：固定步提交当步合成与分数后，如发生可续玩的SPILL，产生一次`SpillDetected{failureId,tick,entityIds}`，engine进入PAUSED并设置run.revive.pendingFailure，不设置最终terminalReason、ended或settleStartedTick，不发RunEnded。UI进入SPILL_OFFER，冻结物理、自动落料、输入和游戏音频，先保存冻结检查点。

如果本局已复活，或该广告点不可用/未达平台首次体验资格/候选不可安全恢复，则仍走正常SPILLED最终结算；不要出现承诺可看的按钮后才发现完全不支持。无广告也能结束本局/再开一局，不能困在待决定页。

同一固定步同时SPILLED与CUP_FULL，保持当前SPILLED优先；技术异常优先回滚且不触发任何广告。失败ID由runId+tick+唯一失败序列构成，重复事件不生成第二弹窗。暂停时tick冻结，无倒计时逼玩家观看。

## 3. UI

标题“小料洒出来了”。说明：“完整观看一段激励视频，清理洒出及杯口附近的小料，保留当前分数继续本局。每局最多复活1次。”展示当前真实分数。

- 主按钮“看广告，复活本局”；次按钮“结束本局”。不点击背景自动选，不默认观看。
- PREPARING：准备中，可取消准备；SHOWING：原生广告控制退出，不用本地定时器强关或自动发奖。
- 提前退出：“未完整观看，尚未复活”，可手动重试或结束；加载失败/无填充同样保留原局并可结束。
- 完成但保存失败：“广告已看完，正在等待保存”，提供“重试保存”；不再次要求观看，不先让玩家操作未持久化局面。
- 成功：“已复活，分数保留”，显示“继续游戏”。玩家明确继续后2秒缓冲再落下一颗，缓冲不重复消费RNG。
- 已用过复活，再洒出：普通结果页，可标“本局复活已使用”，不再给看广告按钮。

后台/返回前台保持原锁和安全暂停；广告回调不隐式resume。关闭游戏重进时，持久化的pendingFailure/pendingAttempt要能回到待决定/待确认；无可信完成凭据不能凭空补发。

## 4. 恢复局面（必须先算好再展示广告）

使用失败当步已经提交的冻结快照，生成确定性的`ReviveCandidate`，不是读取较早存档。先确认所有数值有限、ID唯一、规则兼容；若坏状态，转免费技术故障处理，不能让玩家看广告修bug。

候选清理集：实际洒出的实体；已进入杯但完全位于杯体有限几何外的实体（按现有碰撞容差）；所有`position.y+radius > danger_line_y_du-40`的杯口/上方实体。40du是拟定清理余量，统一配置`revive.clearance_du=40`；包括尚在空中的上方料，避免刚复活即掉满。弹窗需披露清理规则，不仅说“把一颗捡回来”。

保留其它实体位置/等级/ID，清零其线速度/角速度、spillTicks，按杯内状态重算hasEnteredCup，awake等待自然沉降；dangerTicks归零，cup实际offset保留、速度归零，触摸target=actual。清理不发合成/得分/额外物品，不扣已得分，不回收原本并未存在的实体。

RNG和pendingSpawn原封不动；nextEntityId保持单调，不复用被清理ID。tick不倒退，epoch+1让旧命令失效；自动落料nextDueTick在实际继续时设tick+120（2秒），新局/普通暂停仍沿原60tick，避免顺带改变全部玩法。

候选可为空杯，仍保留分数继续；不强行新生成小料填杯。候选须做纯数据几何验证并在受控构建中验证可建世界；候选hash绑定failure/attempt，不能广告完成后用变化后的新局重算。若安全验证失败，不展示广告。

## 5. 最终结算

玩家拒绝、广告不可用而选择结束、第二次洒出，才调用唯一`finalizeFailure(failureId)`：生成一次RunEnded、写一次lastResult/最好成绩并清活动run。看广告失败只回待决定，不自动多结算。复活后最终结算采用assisted分桶，避免标准榜和辅助榜混用。

返回菜单或新局不得静默丢弃pendingFailure，按“结束这局”确认后正常结算；异步广告A完成时若已明确终结A，新局B绝不可得到A复活或额度。
