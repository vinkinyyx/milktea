## 复活规则摘要

- 只针对实际`SPILLED`：询问是否自愿完整观看激励视频，成功后保留当前分数、同一局继续累计。`CUP_FULL`和技术故障不借此收费恢复。
- 每局最多**一次成功复活**；取消、未完整观看、无填充/加载失败不消耗次数。允许同一个失败待处理状态手动重试广告，但不能获得第二次复活。
- “看到规定时间”以Tap原生广告**顶层`isEnded===true`**回调为准，不用客户端倒计时/`show.resolve`/前后台时长推断完成。
- 复活清理洒出及杯口危险区小料，保留分数/最大等级/投放进度/两类RNG/晃杯余额；成功后进入安全暂停，玩家点继续后留2秒落料缓冲。
- 只有奖励和恢复快照原子保存、可恢复后才消费一次复活并显示成功。真实完成但保存失败允许重试领取，不要求重看。
- 额外晃杯与复活广告共享展示互斥，分开记账。看晃杯广告不能复活，看复活广告不加晃杯。复活实际生效即进入assisted成绩桶。

## 本轮实际优化结果

| 指标 | 旧v4候选 | 本轮候选 |
|---|---:|---:|
| Tap ZIP | 4,381,190 bytes | 3,008,364 bytes |
| 所有运行图/特效单份RGBA估算 | 60,251,896 bytes（约57.5MiB） | 24,119,392 bytes（约23.0MiB） |
| 菜单已加载art项 | 71 | 22 |
| 菜单已加载art RGBA估算 | 44,699,616 bytes | 4,982,272 bytes |

RGBA是尺寸预算，不是进程总内存，不等同于400MB平台峰值已降到23MB。DPR3本地对照中画布缓冲均为780×1688，关闭旧retina开关未证明降低缓冲，因此不计入收益。启动采样含测试等待，不用它宣称秒级加速。平台冷启动/进程峰值仍需新包复测。

上述性能对照对应历史0.1.2候选，已归档；当时尚无复活。当前唯一Tap候选及SHA见[平台入口](38-taptap-minigame-current.md)，不能将旧包描述作为当前实现状态。

1. 按docs44定位Tap实际首次失败，加入可操作的加载/错误出口，修复背景空屏。
2. 修复已实现复活中的回读恢复、未完成视频重试和每日上限偏差；补新增故障回归。合并根合同遗漏的复活类型，不能用旧合同覆盖工程。
3. 补齐动画生命周期缺口，复测手机晃杯的最初异常；技术恢复免费，不占复活额度。
4. 用新唯一buildId生成Debug/Web/Tap；同SHA验证冷启、低中高设备内存、10分钟/20次重开及真实广告。旧平台失败在新结果出来前保持开放。
5. 更新唯一候选和交付清单。没有对应设备/广告/平台证据就保留BLOCKED；无授权不上传、提审或发布。
