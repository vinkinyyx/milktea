# 《奶茶挤挤》经典局音乐设计

日期：2026-10-28。状态：原创作曲设计/可编辑符号草稿，尚无最终音频、听测或运行接入。依据 [音频基线](05-audio-spec.md)，不修改玩法配置，不提前实现P1-C音频系统。

## 1. 技能学习与选用

已安装并阅读 [compose-game-music](https://github.com/sora16bit/codex-game-music-skill/tree/main/skills/compose-game-music)，主模式为Compose spec。读取了composition-design-gates、composition-theory-core、output-contracts及标准MIDI写入示例。其价值是先确定玩法功能、动机、乐句、声部连接与循环，再选音色；不将“奶茶”简单等同于不断冒泡音效。

本项目仍以既有84 BPM、60～90秒、低干扰、无人声、三总线及碰撞节流规则为准。上游战斗/自适应配乐示例不引入本游戏。来源、提交及许可证见 [工具安装记录](../evidence/tooling/20261028-cocos-mcp/installation.json)。MIT覆盖工具代码，不替代最终音源/SoundFont/采样授权。

## 2. 设计卡：bgm_classic《杯里的一小会儿》

| 项目 | 决定 |
| --- | --- |
| 场景 | 镜头近看一杯奶茶；玩家观察、拖动、松手，再等待小料落稳与合成 |
| 功能 | 保持轻松、给“想一想再放”留时间；不能催促投放或制造失败焦虑 |
| 节拍 | 84 BPM，4/4，直八分音符，少量弱拍切分；不强制节拍同步操作 |
| 调性 | C大调和声，以C/D/E/G/A五声音阶作主题；B只作内声部导向，避免高音持续尖亮 |
| 时长 | 24小节，96拍，精确理论时长480/7秒≈68.571429秒；A 8小节+A′ 8小节+B/回接8小节 |
| 结构选择 | 24小节由三个8小节乐句组组成，为同时满足84 BPM与60～90秒基线；32小节将约91.43秒，故不采用 |
| 前5秒 | 第1拍给温暖和声/低音，1.5拍出现轻巧四音动机；不用长前奏/店铺噪声 |
| 主动机 | E5–G5–A5–G5；拍位1.5/2/3/3.5，时值0.5/0.75/0.5/0.75拍，短短长短的弹性感主要由留白体现 |
| 回答 | 第2小节E5(第2拍，1拍)→D5(第3.5拍，0.5拍)；第4小节回到C5，不每小节塞满旋律 |
| 负空间 | 第4/8/12/16小节后半留白；主旋律与回答声部不同时密集活动；不加入连续铃声/水泡/白噪底 |
| 输出路线 | 先交多轨MIDI及音符JSON；后用有明确商用许可的音源在DAW渲染，不使用mock正弦波充当成品 |

## 3. 乐句与和声

| 小节 | 和声（每两小节一组） | 旋律/密度/低音设计 |
| --- | --- | --- |
| 1～8 A | C6/9 → Am7 → Fmaj7 → Gsus4/G | 陈述与回答；电钢琴承托，主题只在奇数小节完整出现；低音根音与五度/级进回接 |
| 9～16 A′ | C6/9 → Am7 → Fmaj7 → Gsus4/G | 保留主题轮廓，后半局部节奏移位；12/16小节给投放与碰撞留空间，轻弹拨只在主题休止时回答 |
| 17～24 B/回接 | Am7 → Fmaj7 → Dm7 → Gsus4/G | 主题片段下移或缩短，21～22小节稀疏；23～24低音D→G，旋律以D5/G4开放收尾，指向第1小节C/E |

内声部不随和弦整块跳跃：前两小节E4与A4保持，第3小节C4/E4/G4/A4与前组共享E/A；下一组C4/E4/F4/A4保留C/E/A，仅G→F。低音在第1拍起，和声第1.25拍起，主题第1.5拍起，避免全部声部同时触发。每个和声组中至少一条声部跨小节延续；最终混音通过包络与踏板控制尾音，不能靠全曲大混响掩盖断句。

## 4. 声部与表面

| 声部 | 音区/角色 | 触键、动态与变化 |
| --- | --- | --- |
| electric_piano | C4～A4，和声面 | 柔和电钢琴音源，轻触，组内共同音延续；力度约38～52/127，适度短房间混响 |
| motif | C5～A5，主题线 | 软槌/木质击弦音色，攻击圆润；力度约50～67，尾音约120～250ms，绝不每拍高频敲击 |
| bass | C2～G2，重心与回接线 | 柔软拨弦低音，短而不闷；根音+五度或级进回答，避免手机无法听清的超低频轰鸣 |
| answer_pluck | C4～G4，回答点 | 每4小节一小句，主题休止时出现，力度比主题低；B段减少，不做全程琶音 |
| brush（最终编配可选） | 轻刷/弱拍点 | 只在A′增加，低于主旋律约10～14dB；先听无鼓版，若让等待变焦躁就移除 |

MIDI仅指定GM补丁作为编配提示，不保证播放器音色一致；本次草稿不附音色库、不声称是实录电钢琴。最终选定音源后另记名称/版本/许可。

## 5. 游戏状态、音效与混音

- 普通局：单个循环AudioSource；P1不做多轨实时自适应，MIDI声部用于制作，最终合为一首。
- 危险：维持同曲，仅Music相对当前用户音量降低约4dB，100～200ms平滑变化，危险解除后约300ms恢复。倒计时不延迟到下一拍，也不切战斗曲。
- 合成：主cue按既有等级分组。E/G/A/C/D音阶可作短奖励音家族；一次合成只发一个主音效，表现随机独立，不消费掉落随机数。
- 麻薯/纪录：短和弦或上行三音，Music短暂duck约4dB。结束收束为G4–E4–C4的柔和下降，禁止惩罚性刺耳失败音。危险提示优先级高于装饰声。
- 暂停/后台：冻结音乐播放状态，丢弃过期SFX；恢复不补播碰撞。首次有效点击才尝试音频；加载/播放失败不影响物理tick、投放或计分。
- 重开：先销毁上一局音频所有者，旧异步加载用epoch拒绝；运行时只允许一首BGM。该实现属于P1-C，目前只规定接口行为。
- 初始用户Music35%、SFX70%；最终BGM目标-20～-18 LUFS-I、峰值≤-1dBTP，遵循基线，不使用Asset Forge默认-16LUFS自动归一化替代项目目标。
- 常规碰撞≤6次/秒、同对象≥120ms、低于0.5规格单位/s不播；总并发上限8（含音乐1），详见基线。碰撞声必须听得出材质，不能全部靠旋律变调代替。

## 6. 制作交接与验证

草稿目录：[assets/audio/design](../assets/audio/design/)。`bgm_classic.music.json`记录拍位/时值/力度，`bgm_classic.mid`为Format 1多轨原创新谱草稿。通过`python tools/build_music_sketch.py`重现；脚本不读取密钥、不请求生成服务、不写入client资源。

后续制作：在DAW导入MIDI→选择有授权的电钢琴/软槌/低音→调整触键与声部连接→母版48kHz/24bit立体声→渲染首尾循环与独立混响尾→导出运行MP3 44.1kHz约96kbps。44.1kHz下理论循环3024000采样帧恰好整除；48kHz最近3291429帧，与理论时长差约9微秒，最终必须在采样边界处理。MIDI速度元事件只能用整数微秒/拍，会带来约0.000028秒全曲量化差，不用MIDI播放器时长代替音频循环验收。

实际引擎测试若MP3有缝，按基线评估可支持格式或双源交叉淡化，不擅自承诺无缝。P1完整音频下载软预算2MiB；本BGM按96kbps约0.79MiB，仍要按最终文件及解码内存实测。
